# Установка Hotel Manager server 0.2.0

Это инструкция к предварительной версии. Для проверки используйте новую пустую установку и вымышленных гостей. Существующая частная гостиница не переносится автоматически.

## 1. Подготовить компьютер

- Linux: Node.js 24 LTS, Docker Engine и Docker Compose plugin. Пользователь должен иметь доступ к Docker.
- Windows 10/11 x64: Node.js 24 LTS, Docker Desktop в режиме Linux-контейнеров. Запустите Docker Desktop и дождитесь готовности. Его автозапуск зависит от входа пользователя; для круглосуточной установки без входа в Windows используйте Linux. Нативная служба Windows Server пока не поставляется.
- На время первоначальной сборки нужен интернет. После установки локальный режим не требует внешнего сервиса авторизации.

Скачайте исходники репозитория сервера и откройте папку. На Windows запустите install.ps1 из PowerShell. Если политика компьютера запрещает скрипты, не отключайте её: выполните в терминале этой папки `npm ci`, затем `npm run setup`. На Linux выполните `bash install.sh`.

## 2. Заполнить локальный мастер

Терминал покажет случайный адрес вида `http://127.0.0.1:порт/setup/...`. Откройте его на этом же компьютере. Это локальная страница настройки; сетевой API приложения работает по HTTPS.

Выберите вариант:

| Режим | Что ввести | Что настроить |
| --- | --- | --- |
| Локальная сеть | Закреплённый IPv4 сервера или локальное DNS-имя; адрес его LAN-интерфейса | Закрепить IP в роутере. Разрешить TCP 443 только из гостиничной сети. Не делать проброс из интернета. |
| VPN | IP или DNS-имя сервера в VPN; адрес VPN-интерфейса | Сначала установить Tailscale либо WireGuard на сервер и устройства. Этот вариант подходит при CGNAT. Учётные данные VPN в Hotel Manager не входят. |
| Прямой интернет | Свой домен; адрес интерфейса или «все интерфейсы»; email | DNS A-запись на публичный IP. Разрешить и при необходимости пробросить TCP 443. Caddy использует проверку ACME через 443. При CGNAT нужен VPN или внешний сервер. |

Укажите логин владельца и уникальную парольную фразу от 12 символов. Выберите новую папку установки. Мастер отказывается перезаписывать уже существующую папку. Для разных гостиниц используйте отдельные папки, адреса и тома Docker.

Мастер генерирует пароли базы, ключ шифрования файлов и локальный сертификат независимо для каждой установки. Он ограничивает доступ к папке текущим пользователем/администраторами Windows либо правами 0700 на Linux. Пароль владельца не попадает в образ приложения или публичный compose.json; его начальный файл всё равно является секретом установки.

## 3. Запустить и подключиться

Нажмите «Запустить сервер». Docker соберёт образ и запустит базу, API и HTTPS-прокси. Журнал находится в `install.log` в закрытой папке. Кнопка «Обновить статус» показывает результат. При ошибке настройки и данные сохраняются.

В созданной папке находится `connection.json`. Передайте только этот файл на первое устройство через доверенный канал. В Hotel Manager выберите «QR или файл», откройте файл, проверьте адрес и подтвердите доверие. Войдите с логином и паролем из мастера.

Для LAN/VPN файл содержит SHA-256 сертификата: приложение проверяет конкретный сертификат, его имя и срок. В общих EXE/APK сертификатов гостиниц нет. Публичные сертификаты проверяются системным хранилищем доверия. Нельзя отключать проверку HTTPS или принимать произвольные сертификаты.

В настройках «Сотрудники и доступ» создайте отдельные аккаунты. «Подключить устройство» выдаёт одноразовое приглашение на 10 минут, в виде QR или JSON. Оно даёт доступ выбранному пользователю — не публикуйте и не отправляйте его посторонним.

После первого входа заполните название, контакты и реквизиты своей гостиницы, создайте этажи, категории и номера. Новая установка не содержит готовой структуры гостиницы, гостей, броней или оплат. Общие справочники способов оплаты и шаблоны сообщений не содержат частных сведений.

## 4. Работа и обслуживание

При связи с сервером устройства автоматически синхронизируются. Перед уходом без сети дождитесь завершения синхронизации, включая загрузку фото. Основные операции с бронями, гостями, паспортными данными и оплатой работают локально. Доступ действует до 24 часов после успешной проверки сервера. После истечения срока требуется подключение; неотправленная очередь не удаляется.

Изменение роли, пароля или блокировка отзывает сессии пользователя. Устройство без сети узнает об этом при подключении либо заблокируется после окончания допуска. Прежний профиль с неотправленными изменениями сохраняется отдельно, но его автоматическое восстановление после изменения прав ещё не реализовано. Не меняйте права перед синхронизацией важных правок без необходимости.

В терминале созданной папки установки:

```sh
docker compose -f compose.json ps
docker compose -f compose.json logs --tail 100 api
docker compose -f compose.json stop
docker compose -f compose.json up -d
```

Не используйте `down -v` на рабочем сервере: это удаляет базу и вложения. Не публикуйте папку установки, Docker volumes, backups и secrets. `.gitignore` — дополнительная защита, а не замена контроля содержимого.

Для восстанавливаемой резервной копии необходимы согласованные копии PostgreSQL, тома files, secrets и сертификатов. Законченный мастер резервного копирования/восстановления в 0.2.0 отсутствует. До рабочих данных нужно проверить восстановление на отдельном сервере.

Локальный сертификат действует один год. Автоматическая замена с передачей нового доверия устройствам ещё не реализована; запланируйте обновление сертификата и повторную передачу connection.json. Публичный сертификат Caddy продлевается при доступности DNS/443.

## Перед публичным выпуском

Проверить чистые Linux/Windows, физический Android, отзыв доступа и 24-часовой офлайн-сценарий, восстановление резервной копии и подпись дистрибутивов. Код CI для Docker smoke test добавлен, но наличие workflow не означает, что он уже успешно выполнился в GitHub.
