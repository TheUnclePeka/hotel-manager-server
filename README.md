# 🏨 Hotel Manager · Server

**Часть Hotel Manager — системы для небольшой гостиницы.**

Код проекта написан нейросетью по задачам и требованиям **[TheUnclePeka](https://github.com/TheUnclePeka)** для личного пользования в своей маленькой гостинице. Эта обезличенная версия опубликована на GitHub для тех, кому она может понадобиться. Можно использовать и изменять проект под свои задачи на условиях [MIT](LICENSE).

[Главная страница проекта](https://github.com/TheUnclePeka/hotel_manager) · [Установка](https://github.com/TheUnclePeka/hotel_manager/blob/main/docs/INSTALL.md)

---

Предварительная версия 0.2.0, MIT. Независимый репозиторий сервера для одной гостиницы. В исходниках и образе нет клиентских адресов, паролей или ключей установки.

Реализованы отдельные пользователи, роли owner/manager/reception/viewer, Argon2id, одноразовые приглашения на 10 минут, access token на 15 минут и ротация refresh token на 30 дней. Повторное использование refresh token отзывает устройство. Сервер проверяет права синхронизации, файлов, отчётов и долгоживущих соединений. Каждая новая база получает собственный случайный идентификатор установки.

## Установка

[Пошаговая инструкция](INSTALL.md). Мастер создаёт закрытую папку конфигурации и Docker Compose для Linux или Windows с Docker Desktop. Предлагает LAN, VPN и прямой HTTPS. Требуются Node.js 24+ и Docker Compose; мастер не устанавливает Docker и не меняет роутер или брандмауэр.

```sh
npm ci
npm run setup
```

## Разработка и проверки

```sh
npm ci
npm run build
npm test
npm run test:security
npm run test:installer
```

`test:security` запускает отдельную временную PostgreSQL на свободном loopback-порту, использует синтетические данные и останавливает её в finally. Существующие службы PostgreSQL не используются. `test:installer` проверяет уникальность ключей, сертификаты, запрет перезаписи и защиту локального мастера.

`npm run test:deployment` дополнительно проверяет настоящее развёртывание Docker, HTTPS и вход владельца на отдельном порту 19443. Нужен работающий Docker. Команда создаёт собственный проект Compose со случайным именем и удаляет только его тестовые тома после завершения.

`npm run dev` предназначен для разработки: PostgreSQL и API доступны через loopback, секреты находятся в игнорируемой `.dev-data`. Клиентам всё равно требуется HTTPS. Для внешней PostgreSQL используйте `.env.example`, собственный FILES_KEY и `node --env-file=.env dist/main.js`. Переменные `DATABASE_URL_FILE`, `FILES_KEY_FILE`, `ADMIN_PASSWORD_FILE` читают Docker secrets. `SINGLE_PRIVATE_PROXY=true` допустим только за одним частным прокси без прямого доступа к API; по умолчанию доверие forwarded-заголовкам отключено.

Миграция 013 отзывает все сессии старого единственного аккаунта. Перед применением к данным нужна резервная копия. Владелец восстанавливается локальной командой `node dist/cli.js set-password <login>`; она отзывает его устройства, универсального пароля нет.

## Границы предварительной версии

Мастер и конфигурация проверены локально. [GitHub Actions на Linux](https://github.com/TheUnclePeka/hotel-manager-server/actions/runs/39560575674) проверил Docker-развёртывание, HTTPS и вход владельца. Пользовательская установка на чистых Linux/Windows ещё требует проверки. Windows Docker Desktop запускается после входа пользователя, это не нативная служба Windows Server. Автоматические резервные копии/восстановление, обновление локального сертификата и подпись выпусков ещё не оформлены в законченный пользовательский сценарий. Не выдавайте предварительную сборку за готовый выпуск для реальных паспортных данных.

`THIRD_PARTY_NOTICES.txt` содержит сведения об установленных npm-зависимостях. Override uuid для exceljs устраняет известное предупреждение npm audit; работоспособность выгрузки XLSX проверяется интеграционным тестом.
